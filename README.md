# pngparse

A tiny, dependency-free PNG **structural inspector and validator** in Go
(standard library only). It does not decode pixels; it validates the file's
*container*: the signature, every chunk's length/crc, the IHDR, palette and
text-chunk rules.

## What a PNG looks like

A PNG file is a fixed 8-byte signature (`0x89 'P' 'N' 'G' CR LF 0x1A LF`)
followed by a chain of chunks. Each chunk is a 4-byte big-endian length, a
4-character type, that many data bytes, and a 4-byte CRC-32. The chunk type's
first letter is uppercase for *critical* chunks (IHDR, PLTE, IDAT, IEND — a
decoder must understand these) and lowercase for *ancillary* chunks (tEXt,
zTXt, iTXt, … — optional metadata). Every PNG must begin with exactly one
IHDR and end with exactly one length-0 IEND; the image data lives in one or
more IDAT chunks that must be consecutive. That is the whole file format;
pngparse inspects all of it.

## CLI

```sh
go build ./cmd/pngparse            # produces ./pngparse

pngparse file.png                  # human-readable report; exit 0 = valid
pngparse --json file.png           # machine-readable JSON report
pngparse --extract iTXt file.png   # print extracted text entries
pngparse --hash file.png           # SHA-256 hex of the raw bytes
pngparse --version | --help
```

Exit codes: `0` valid, `1` not a PNG / structural problem / bad CRC /
unreadable file, `2` usage error.

## Chunk table

For every chunk the report prints its byte offset, 4-character type, payload
length and CRC verdict (`OK`/`BAD`). The CRC is standard CRC-32/ISO-HDLC
(IEEE 802.3): the PNG spec computes it over the **chunk type plus data**
(with an initial value of all ones, which is exactly what
`crc32.ChecksumIEEE` implements). A bad CRC is a *problem*, never a parse
fatal: the chunk stays inspectable and its `CrcValid` flag is `false`.

## IHDR decoding

The 13-byte IHDR payload is decoded into: width, height, bit depth, color
type, compression method, filter method and interlace method, with friendly
names for color type (grayscale / truecolor (RGB) / indexed-color /
grayscale+alpha / RGBA) and interlace (none / Adam7). Bit depth is
cross-checked against the specification matrix:

| Color type | Name             | Valid bit depths |
|------------|------------------|------------------|
| 0          | grayscale        | 1, 2, 4, 8, 16   |
| 2          | truecolor (RGB)  | 8, 16            |
| 3          | indexed-color    | 1, 2, 4, 8       |
| 4          | grayscale+alpha  | 8, 16            |
| 6          | RGBA             | 8, 16            |

Indexed images (color type 3) must carry a PLTE chunk with entries count
`<= 2^bitdepth`; PLTE lengths must be divisible by 3; PLTE is forbidden for
grayscale/grayscale-alpha and must precede the first IDAT. Compression and
filter methods must be 0, interlace must be 0 or 1.

## Text chunks

`tEXt` (Latin-1 keyword + text), `zTXt` (zlib-compressed Latin-1 text) and
`iTXt` (UTF-8, optionally compressed) are read back in full, including
non-ASCII Latin-1 bytes; compressed payloads are inflated with
`compress/zlib` when the compression method byte is 0 (anything else is
warned about and skipped).

## Library

```go
p, err := pngparse.ParseFile("photo.png")
for _, prob := range p.Problems { ... }
chunks, err := pngparse.ParseChunks(data) // raw walk, CRC recorded per chunk
r := pngparse.Validate(data)              // graceful, never fails
fmt.Print(pngparse.Describe(p))
```

See `signature.go`, `chunks.go`, `png.go`, `text.go` — each type and function
is documented in place. The `cmd/pnggen` tool regenerates the `testdata`
fixtures.

## Tests & CI

`CGO_ENABLED=0 go test ./...` builds small PNGs in memory (1x1 RGB,
1x1 indexed, 2x2 RGB with tEXt/zTXt/iTXt, plus deliberately corrupt and
truncated variants), checks the old-style signature and the full
bit-depth/color-type matrix, round-trips Latin-1 text, and runs the compiled
binary against fixtures checking stdout content and exit codes. The
`testdata/` fixtures are real, decodable PNGs (verified with
`image/png`); regenerate them any time with `go run ./cmd/pnggen`.

CI runs `go vet ./...` and `go test ./...` with `CGO_ENABLED=0` on
`setup-go@v5`.
